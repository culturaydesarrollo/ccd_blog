Publicar un post en el blog

Instructivo para crear, revisar y publicar artículos en Cultura y Desarrollo

Proyecto Astro · Actualizado: septiembre de 2026

1. Estructura del contenido

Los artículos se guardan como archivos Markdown dentro de:

src/content/blog/

Por ejemplo:

src/content/blog/mi-nuevo-articulo.md

El nombre del archivo se convierte en la dirección del artículo. Usa minúsculas, números y guiones para obtener una URL clara.

2. Imagen del autor

Guarda las fotografías en:

public/images/

Ejemplo:

public/images/hector-galeano.jpg

La imagen debe ser una fotografía optimizada y preferiblemente cuadrada. Si no se indica una imagen, el sitio usa el avatar institucional por defecto.

3. Crear el archivo Markdown

Todo post empieza con un bloque de datos llamado frontmatter. Debe estar entre dos líneas de tres guiones:

---\ntítulo y datos del post\n---

Ejemplo completo:

---
title: "El patrimonio y las comunidades"
description: "Una reflexión sobre la gestión comunitaria del patrimonio."
pubDate: "2026-09-09"
author: "Héctor Galeano David"
authorImage: "/images/hector-galeano.jpg"
authorBio: "Autor y gestor cultural interesado en el patrimonio vivo y el desarrollo territorial."
category:
  - "Cultura"
  - "Patrimonio"
tags:
  - "Colombia"
  - "Gestión cultural"
---

## Título de una sección

Escribe aquí el contenido del artículo en Markdown.

Campos obligatorios

CampoUsoEjemplo
titleTítulo visible del artículo."El patrimonio y las comunidades"
descriptionResumen breve para la portada."Una reflexión..."
pubDateFecha de publicación."2026-09-09"
authorNombre del autor."Héctor Galeano David"
categoryUna o varias categorías.Lista YAML

authorImage, authorBio, tags e image son opcionales. Las categorías y etiquetas deben escribirse como listas.

Biografía del autor

La biografía aparece en un pop-up al hacer clic en la foto del autor. Se recomienda escribir entre 250 y 600 caracteres; hasta 800 sigue siendo cómodo de leer. Esta extensión es solamente una recomendación ideal de legibilidad, no una restricción técnica: el sistema acepta textos más largos, aunque pueden ocupar más espacio en pantallas pequeñas.

Para textos largos, usa el formato multilinea de YAML:

authorBio: >
  Autor y gestor cultural con experiencia en patrimonio,
  participación comunitaria y desarrollo territorial.
  Su trabajo se centra en fortalecer iniciativas culturales.

4. Escribir el contenido

Después del segundo ---, escribe el artículo usando Markdown:

  • # para títulos principales y ## para secciones.
  • **texto** para negrita.
  • [texto](https://ejemplo.com) para enlaces.
  • Una línea en blanco entre párrafos.
Consejo: revisa ortografía, enlaces, nombres propios y que la descripción represente fielmente el contenido.

5. Categorías, etiquetas e imágenes

Cada categoría genera automáticamente una página agrupada:

/categorias/cultura/
/categorias/patrimonio/

Al agregar una categoría nueva en el frontmatter, Astro generará su página en el siguiente build. Las etiquetas funcionan de forma similar en /tags/.

Para una imagen destacada del artículo, guárdala en public/images/ y añade:

image: "/images/nombre-de-la-imagen.jpg"

6. Revisar el post en local

  1. Abre una terminal en la carpeta principal del proyecto.
  2. Inicia el servidor:
npm run dev

Abre http://127.0.0.1:4321/ y comprueba la portada, la imagen del autor, las categorías, el artículo y los enlaces.

7. Validar antes de publicar

Validar significa comprobar que el post está bien escrito para el sistema antes de enviarlo a producción. La validación se hace en la terminal integrada de VS Code, ubicada en la carpeta principal del proyecto, y también en el navegador local.

7.1 Comprobar tipos y estructura

Este comando revisa la configuración TypeScript y los archivos Astro en busca de errores de sintaxis, campos mal escritos o incompatibilidades:

npm run typecheck

Si termina sin errores, la estructura del contenido y del código es válida.

7.2 Generar el sitio completo

Este comando ejecuta el proceso real de generación estática. Comprueba el frontmatter, las rutas de posts, categorías y etiquetas, las imágenes y las plantillas:

npm run build

Debe terminar con un mensaje de finalización correcta y mostrar las páginas generadas.

7.3 Revisar visualmente

Inicia el servidor local desde la misma terminal:

npm run dev

Después abre http://127.0.0.1:4321/ en el navegador. Comprueba la portada, la foto y el pop-up del autor, la biografía, las categorías, las etiquetas, la página individual, las imágenes y los enlaces.

Prueba también la URL directa del post, por ejemplo:

http://127.0.0.1:4321/mi-nuevo-articulo/
Orden recomendado: primero ejecuta npm run typecheck, después npm run build y finalmente revisa el resultado en el navegador local.
Si aparece un error: revisa primero la sintaxis YAML del frontmatter, las rutas de las imágenes, las comillas y que las listas estén correctamente indentadas.

8. Publicar

Cuando el typecheck y el build terminen correctamente:

  1. Guarda los cambios del post, las imágenes y los archivos modificados.
  2. Sube los cambios al repositorio o al servicio de despliegue utilizado por el proyecto.
  3. Espera a que finalice el build de producción.
  4. Abre el dominio del blog y verifica el artículo publicado.

Recuerda que las páginas de categorías y etiquetas se generan durante el build; al crear una categoría nueva debes volver a desplegar.

9. Cerrar el servidor local

Cuando termines de revisar el post, detén el servidor de desarrollo para liberar el puerto y cerrar la tarea local:

  1. Vuelve a la terminal donde está ejecutándose npm run dev.
  2. Presiona Ctrl+C.
  3. Confirma que la terminal vuelva a mostrar el indicador de comandos.

Si Astro quedó ejecutándose como proceso gestionado, también puedes detenerlo con:

npx astro dev stop
Importante: cerrar la pestaña del navegador no detiene el servidor. Debes detenerlo desde la terminal.
